# Local TLS harness

Host-accurate local mode for `https://*.app.lvh.me` and `https://admin.lvh.me`.

## Files

- `Caddyfile` — generated by `bun run setup:env`. Do not hand-edit.
- `mkcert-sans.txt` — generated SAN list. Do not hand-edit.
- `bootstrap.sh` — hand-written. Mints `certs/{cert,key}.pem` via mkcert.
- `certs/` — gitignored. Bootstrapped certs land here.

## One-shot

```sh
bun run setup:env                            # write Caddyfile + SAN list
local-harness/bootstrap.sh                   # mkcert -install + cert mint
# The Caddyfile uses paths relative to the harness dir, so `cd` first:
(cd local-harness && caddy run --config Caddyfile)   # serve https://*.app.lvh.me
```

`https://acme.app.lvh.me` resolves via `lvh.me`'s public DNS (any subdomain
points at `127.0.0.1`). The seed script (`bun run seed:dev`) provisions the
matching tenant org so the host resolves end-to-end.

## When to regenerate

- `.env` changed any host-config key: `bun run setup:env`.
- New SAN added (e.g., a custom hostname): `local-harness/bootstrap.sh`.
- Caddy edits land out-of-band: do not. Edit the renderer in `scripts/lib/host-config.ts` and re-run `bun run setup:env`.
