# Environment Variables

## How it works

Wrangler has three mechanisms for env vars, each with a distinct role:

| Mechanism | What goes here | Committed to git? |
|-----------|---------------|-------------------|
| `vars` in `wrangler.jsonc` | Non-secret config (development defaults) | Yes |
| `.dev.vars` | Secrets for local dev | No (gitignored) |
| `wrangler secret put` | Secrets for production | No (Cloudflare dashboard) |
| `--var KEY:value` at deploy | Production overrides for non-secret vars | No (in CI script) |

## Why not wrangler environments?

Wrangler `env.*` blocks do NOT inherit bindings (kv, hyperdrive, services, queues, durable objects, etc). Using them would require duplicating every binding definition. The `--var` flag at deploy time avoids this entirely.

## Why not .dev.vars for NODE_ENV?

`.dev.vars` is for secrets only. When `secrets.required` is defined in `wrangler.jsonc`, wrangler only loads keys listed there from `.dev.vars` -- all other keys are silently ignored. Even without `secrets.required`, `.dev.vars` values cannot override `vars` already defined in config.

## Local development

`wrangler dev` reads vars directly from `wrangler.jsonc`. All top-level `vars` default to development values:

```jsonc
"vars": {
  "NODE_ENV": "development",
  "APP_URL": "http://localhost:8787",
  "CORS_ORIGINS": "http://localhost:3001"
}
```

Secrets come from `.dev.vars` (generated by `bun run setup:env` from root `.env`).

## Production deployment

Deploy overrides env-specific vars with `--var` flags. The `deploy` script in each worker's `package.json` already includes `--var NODE_ENV:production`. When deploying to a real environment, also override `APP_URL` and `CORS_ORIGINS`:

```bash
wrangler deploy --minify \
  --var NODE_ENV:production \
  --var APP_URL:https://api.example.com \
  --var CORS_ORIGINS:https://example.com
```

Other vars that may need production overrides: `EMAIL_FROM`, `EMAIL_FROM_NAME`.

Production secrets are set once via `wrangler secret put KEY`.

## Adding a new env var

- **Non-secret, same in all environments**: Add to `vars` in `wrangler.jsonc`
- **Non-secret, differs per environment**: Add to `vars` with dev default, add `--var` override to deploy script
- **Secret**: Add to `secrets.required` in `wrangler.jsonc`, add to `.dev.vars` locally, run `wrangler secret put` for production, update `setup-env.sh` and root `.env`

## File overview

| File | Purpose |
|------|---------|
| Root `.env` | Single source of truth for all local values (Bun auto-loads) |
| `packages/db/.env` | Drizzle Kit database credentials (generated by `setup:env`) |
| `apps/server/.dev.vars` | Server worker secrets (generated by `setup:env`) |
| `apps/auth/.dev.vars` | Auth worker secrets (generated by `setup:env`) |
| `apps/web/.env` | Vite public vars like `VITE_SERVER_URL` (generated by `setup:env`) |
